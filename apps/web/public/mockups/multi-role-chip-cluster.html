Multi-role rendering — Approach 3: chip cluster

One AbilityRow per ConnectionGroup, regardless of sub-role count. The sub-role labels sit at the start of the row as a horizontal chip cluster ("[AT-PAYOFF] [MOVE] [BUFF] [SEARCH]"), followed by a single combined description that summarizes how the card supports the location.

Pros

• Locks Location Control to a single 61-90px row regardless of sub-role count (2 to 8).
• Preserves enumeration (all sub-role names visible at a glance).
• Sub-role chips can be hover-activated for individual descriptions later.

Cons

• Loses the per-sub-role descriptions in the visible state — combined description has to be more abstract.
• Many sub-roles (5+) might wrap the chip cluster to 2 rows, growing the AbilityRow taller.
• Chip cluster is a new component pattern that doesn't exist elsewhere yet.
